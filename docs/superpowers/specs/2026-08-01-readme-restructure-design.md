# README 重构设计

## 目标

把仓库首页从以“结构化 Bug 查询”为主的操作说明，重构为兼顾求职作品集展示
和本地开发部署的项目入口。读者应先理解项目解决的问题、架构与工程价值，
再按需要查看安装、配置、运行和验证步骤。

## 受众

- 面试官和技术评审：快速了解 AI 测试 Agent 的落地能力与工程边界。
- 测试开发人员：能够在本地安装依赖、启动服务并复现自动测试。
- 项目维护者：能够识别当前完成状态、限制和后续路线图。

## 信息结构

README 按以下顺序组织：

1. 项目定位、状态标签和核心亮点。
2. 问题背景、Agent 工作流与整体架构。
3. 技术栈，以及本地模型和确定性代码的职责边界。
4. 已完成能力、自动测试指标和当前限制。
5. 快速开始、环境变量和各服务启动方式。
6. Open WebUI 接入、命令行演示和测试命令。
7. 数据与凭据安全、目录结构和路线图。

## 内容边界

- 保留现有 Bug 同步、OpenAPI 查询、Agent 配置、Open WebUI Pipe 和测试说明。
- 合并重复的架构、启动、指标和安全说明，避免同一信息在多个章节反复出现。
- 不写入真实账号、Token、交易密码、Cookie、数据库或浏览器认证状态。
- 明确区分自动测试验证过的代码契约与尚未完成的真实钱包 E2E 验收。
- 不把未组装的生产 `ExecutionBackend` 或尚未适配的页面选择器描述为已完成。

## 验收标准

- GitHub 首页首屏能够说明项目用途、核心技术和当前状态。
- 新用户可依据 README 完成安装、配置、启动、查询和测试。
- 所有命令、路径、端口和文件名与当前仓库实现一致。
- Markdown 格式检查通过，README 不包含秘密信息或未经验证的结果。
